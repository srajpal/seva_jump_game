# Google Play tester recruitment

Researched September 18, 2026. Personal developer account selected by the owner. No testing service purchased, community joined, or recruitment message sent.

## Requirement and timing

Google requires at least 12 testers opted into the closed test continuously for at least 14 days before applying for production access. Engagement, feedback, and improvements must be described honestly in the application; meeting the count does not guarantee approval. Use the Play Console counter as the source of truth, not a community timer. Browser play and internal-track testing do not replace the closed test.

Source: https://support.google.com/googleplay/android-developer/answer/14151465

## Proposed approach for Seva Jump

1. Finish account verification and the signed Android candidate, then smoke-test on the internal track.
2. Recruit 16-20 committed testers as a buffer, using App Hive if daily reciprocal testing is feasible, or evaluate Testers Community's paid plan. Add a few reliable personal/community testers for deeper game feedback.
3. Publish the closed-test release and provide its opt-in link, supported test countries and installation instructions. Each tester must actually opt in using the Google account they use in Play.
4. Ask testers to remain opted in for the full period and play regularly. A suggested 5-10 minute session is our testing plan, not a Google-mandated session length.
5. Track device model, Android version, opt-in date, feedback and resolution. Keep tester email lists outside the public source repository. Use private Play feedback or an agreed feedback channel; no analytics need to be added to the game.
6. Apply only when Play Console confirms eligibility and blocking bugs are resolved. Describe actual feedback and fixes; do not copy invented production-access answers from a provider.

## Testing brief

- First session: install, complete the guide, try both characters, assess text size and touch controls.
- Early sessions: try all four modes; report confusing instructions, unfair jumps, bird collisions and difficulty.
- Middle sessions: check upgrades, badges, sound, pause/resume, Android Back and saved progress after restarting.
- Later sessions: test airplane-mode launch, interruptions, longer play and phone/tablet layout. Attempt natural Arcade and Challenge completion and describe where progress stops.
- Final sessions: install fixes and verify reported issues. Reset only when intentionally testing reset, since it erases local progress.

For every issue, request what happened, expected behavior, reproduction steps, device/Android version and an optional screenshot. Ask for honest private feedback, not public ratings.
