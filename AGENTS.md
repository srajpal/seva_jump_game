# SevaJump contributor guide

## Project at a glance

SevaJump is a free, offline-first, touch-friendly vertical jumping game for ages 8-15. The browser game is the source of truth; Capacitor packages it as the portrait-only Android app. Preserve the no ads, purchases, accounts, analytics, and gameplay-network-dependency model.

## Where to work

- `index.html`, `styles.css`, and `game.js` are the game shell, responsive UI, canvas gameplay, input, and rendering.
- `game-config.js` contains gameplay tuning. Keep shared behavioural calculations in `game-rules.js` so tests can exercise them.
- `assets/` contains source pixel-art assets. Do not overwrite assets or add generated variants unless the task requires them.
- `tests/` contains standalone Node checks; extend the most relevant check when changing rules, procedural generation, or balance.
- `android/` is the Capacitor wrapper. `android/app/src/main/java/org/sevajump/game/MainActivity.java` owns Android system bars, insets, and immersive-gameplay integration.
- `www/` is generated by `npm run web:sync`; never hand-edit it.
- `screenshots/` holds local phone/tablet review captures and contact sheets. It is intentionally gitignored; do not stage its contents unless the task explicitly requires a curated release asset.

Read `README.md` for game behaviour/build context. Use `RELEASE_CHECKLIST.md` for release validation and `STORE_LISTING.md` for Play Store copy and declarations. Inspect only the files relevant to the task; avoid unrelated refactors or feature expansion.

## Development and validation

There is no formatter or lint script. At minimum, syntax-check changed JavaScript and run the targeted Node check. Run the full suite for gameplay/configuration changes or before a release:

```powershell
node --check game.js
node tests\rule-checks.js
node tests\full-run-checks.js
node tests\endless-bird-checks.js
node tests\hard-mode-checks.js
node tests\power-jump-checks.js
node tests\soak-test.js
```

Build the Android debug APK with:

```powershell
npm install
npm run android:debug
```

`android:debug` syncs the web source into `www/` before building. Test Android UI changes on at least a phone-sized and tablet-sized device/emulator; retain the un-stretched canvas and safe-area/system-bar behaviour. Test browser changes in a modern desktop and mobile browser when they affect layout or input.

## Cross-cutting rules

- Keep the web source and Capacitor wrapper aligned. If Android-visible web assets change, run the sync/build rather than editing copied files.
- Progress is deliberately local-only in `localStorage`; do not add telemetry, remote services, sign-in, ads, or third-party SDKs without an explicit product/privacy decision and matching documentation/store-declaration updates.
- Preserve portrait orientation and Android Back/system-bar behaviour unless the task explicitly changes it.
- Treat gameplay tuning as testable: update relevant rule/procedural checks with changes to reachability, mode completion, boosts, birds, collectibles, or platform pacing.
- Before an Android upload, increment the visible version in `index.html`, `package.json`, and `android/app/build.gradle` (`versionName` and `versionCode`), then follow `RELEASE_CHECKLIST.md`. Do not commit keystores, signing files, APKs, AABs, or local Android configuration.
- Keep Sikh terminology and the gurdwara-inspired setting respectful; route lasting wording or imagery decisions through the appropriate user-facing documentation when needed.
